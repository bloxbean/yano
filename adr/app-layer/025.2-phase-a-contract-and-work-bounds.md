# ADR-025.2 Phase A — Final v1 contract and work bounds

## Status

Implemented and independently verified on 2026-08-04.

## Frozen contract outputs

- authenticated-map genesis codec: `4`;
- authorization kinds: `open=0`, `owner=1`, `member=2`,
  `governed-role=3`, `approval=4`;
- final action/evidence CDDL:
  `META-INF/yano/contracts/authenticated-map/v1/`
  `authenticated-map-authorization-v1.cddl`;
- cross-language vectors:
  `META-INF/yano/contracts/authenticated-map/v1/`
  `authorization-vectors.properties`;
- independent verifier:
  `appchain/appchain-stdlib-contracts/scripts/`
  `verify-authenticated-map-authorization-vectors.py`; and
- role/governance CDDL:
  `META-INF/yano/contracts/role-workflow/v1/role-workflow-v1.cddl`.

The Java and Python implementations independently reproduce the governed
genesis ID, complete action commitment, actor and administrator signing
preimages, Ed25519 signatures, proof of possession, `(actorId,
authorizationId)` key, and the one-key-per-`proposalId` approval namespace.

## Consensus bounds

| Bound | Final v1 maximum |
|---|---:|
| Evidence items per command | 32 |
| Covered mutation indexes per evidence item | 128 |
| Genesis organizations | 64 |
| Genesis actors | 128 |
| Genesis actor keys | 256 |
| Genesis direct + approval policies | 128 |
| Encoded governed genesis record bytes | 262,144 |
| Administrator actors | 64 |
| Pending governed mutations | 1,024 |
| Pending approvals | 4,096 |
| Pending per actor | 64 |
| Pending per policy | 256 |
| Pending per authority | 256 |
| Pending per deadline bucket | 128 |
| Expiry work per block | 256 |
| Authority-handover supersession work | 256 |
| Query page size | 100 |
| Governed crypto work units per block | 512 |

One governed crypto work unit is one inner actor signature verified by the
strict dual-verifier profile. Actor map authorizations, approval decisions,
and administrator votes each cost one unit. Structural/canonical checks run
before crypto. Authoritative apply counts a unit before attempting the
signature and repeats any admission verification. The count follows the
committed component/workflow order. A command that would exceed the cap is a
deterministic no-op with `CRYPTO_WORK_EXCEEDED`; it cannot consume evidence or
partially mutate state.

## Measurement and cap decision

Reference run:

- runtime: OpenJDK `25.0.2+12-LTS`;
- iterations after warm-up: 50,000;
- strict SunEC + CCL Ed25519 verification: approximately `393,782 ns` per
  governed work unit;
- default block interval: `2,000 ms`;
- default block message cap: `5,000`; and
- default serialized block cap: `4 MiB`.

The block byte/message bounds alone permit thousands of small signed commands,
so they are not a sufficient fence for the added inner signature work. The
initial 2,048-unit candidate measured about `818.5 ms`, or `40.9%` of the
default interval, before state, validator, proof, persistence, outer-message,
and finality work. It was rejected.

The final 512-unit cap measured about `201.6 ms`, or `10.1%` of the default
interval on the reference JVM. Phase G must repeat the measurement on the
supported native runtime. A regression beyond the qualification headroom is a
release blocker; it is not permission to raise the v1 cap locally.

Reproduce the measurement with:

```bash
./gradlew \
  :appchain-stdlib-contracts:benchmarkAuthenticatedMapAuthorizationCrypto
```

The machine-local JSON report is written under
`appchain/appchain-stdlib-contracts/build/reports/adr0252/`.

## Logical state and proof namespaces

The authenticated-map component owns entries, receipts, and consumption:

```text
yano-authenticated-map-internal-v1 / genesis
yano-authenticated-map-receipts-v1 / messageId
yano-authenticated-map-direct-consumption-v1 /
  version:u8 || actorLength:u16be || actorId || authorizationId
yano-authenticated-map-approval-consumption-v1 / proposalId
```

The actor and role components own:

```text
o/{organizationId}/current             o/{organizationId}/r/{revision}
a/{actorId}/current                    a/{actorId}/r/{revision}
d/{directPolicyId}/current             d/{directPolicyId}/r/{revision}
p/{approvalPolicyId}/current           p/{approvalPolicyId}/r/{revision}
h/{authorityId}/current                h/{authorityId}/r/{revision}
g/{mutationId}                         q/{proposalId}
x/g/{height16}/{mutationId}            x/q/{height16}/{proposalId}
i/g/a/{actorId}/{mutationId}           i/g/h/{authorityId}/{mutationId}
i/q/a/{actorId}/{proposalId}           i/q/p/{policyId}/{proposalId}
```

`height16` is a lower-case, fixed-width, 16-digit hexadecimal height. Current
pointer values are positive unsigned 64-bit big-endian binary revisions, not
CBOR. Composite physical namespacing is added in Phase B and must be returned
verbatim by the Phase E proof APIs.
