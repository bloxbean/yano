# ADR-025.3: Governed In-Place Validator Rotation for Authenticated Map

## Status

**Placeholder.** Not accepted, not scheduled, no design decisions made. This
document only records a consciously deferred v1 capability and the operational
trigger that would justify designing it. It must be replaced by a full ADR
(problem framing, contract deltas, phases, qualification) before any
implementation work.

## Context

The frozen `authenticated-map` v1 contract (ADR-025, ADR-025.1, ADR-025.2)
pins every value validator at genesis: a plugin validator is bound by its
descriptor and the `ARTIFACT_CLOSURE` digest of its bundle, and the runtime
resolver fails closed when the packaged bundle's digest differs from the
genesis binding. This is deliberate — validators execute inside consensus, so
silently changing their bytes could make replayed history accept or reject
differently than the history that was actually finalized.

The consequence, confirmed operationally on 2026-08-05: routine node upgrades
are safe (the closure digest is canonical and content-scoped, so unrelated
`yano.jar` changes reproduce it bit-for-bit), but a *deliberate* validator
change — for example a bug fix in a schema or plugin validator — has no
in-place path on an existing chain. Today's options are a new genesis (a new
chain) carrying the new descriptor, or keeping the code the chain's history
was validated under.

## Deferred capability

Governed validator rotation, by analogy with direct-role policy revisions:
immutable validator revision records, a current pointer, and an
administrator-governed activation height, so that history before the
activation height replays under the old validator and history after it under
the new one.

Known hard problems any real design must answer (recorded, not resolved):

- **Replay determinism** requires every historical validator revision to
  remain resolvable forever; artifact retention/availability becomes a
  consensus concern, not a packaging concern.
- **Digest re-pinning** must be part of the governed record, and the
  fail-closed resolver semantics must become height-aware.
- **Work bounds:** validator execution cost is fenced by the Phase-A frozen
  bounds; a rotation path must not create a route around them.
- **Proof/console surface:** revision records, current pointers, and
  activation facts would need the same exact-record, proof-bundle, and
  console treatment ADR-025.2 gave policies and authorities.

## Trigger for promotion

Promote this placeholder to a full ADR when a concrete need appears in
practice — the first time a deployed authenticated-map chain requires a
validator correction that cannot reasonably be served by a new chain genesis.
Until then, the v1 freeze stands unchanged.
