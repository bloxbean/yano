# ADR-025.1 Phase C — custom validator plugins

Status: implemented and qualified on 2026-08-04.

## API and module boundary

The narrowly scoped public SPI lives in `core-api` under
`com.bloxbean.cardano.yano.api.appchain.authmap`. It consists of the validator,
factory, typed verdict, immutable initialization context, and host resolver
bridge. `ValidatorDescriptor` remains part of the authenticated-map wire and
genesis contract in `appchain-stdlib-contracts`; there is no separate validator
API module.

The first-party implementation bundle is the separate
`appchain-authenticated-map-validators` module. Keeping implementations outside
`appchain-stdlib` prevents an ambient ServiceLoader provider from bypassing the
manifest-required plugin catalog. The additive SPI and the new
`authenticated-map-validator` contribution advance the global plugin API level
from 1 to 2.

## Consensus activation

A plugin descriptor pins its provider id, `authenticated-map-validator-v1`
contract, canonical parameter map, and raw 32-byte SHA-256 artifact-closure
digest in genesis. Runtime resolution succeeds only when the selected provider:

- belongs to an explicitly allow-listed manifested bundle;
- has `ARTIFACT_CLOSURE` evidence whose digest exactly matches genesis;
- reports the pinned provider id and contract version; and
- constructs a non-null validator from the defensive initialization snapshot.

Any mismatch fails state-machine construction before consensus participation.
Normal `REJECT` verdicts use authenticated receipt code
`ERROR_VALUE_VALIDATOR = 12`. Unexpected runtime failures escape the transition
path and fail the node closed; they are never converted into rejection receipts.
The same validator runs during proposal pre-validation, authoritative apply,
and startup validation of genesis initial entries. Mutable key, value, and
parameter arrays are defensively copied across the plugin boundary.

## Conformance and reference bundle

`AuthenticatedMapValidatorConformance` exercises a bounded corpus through fresh,
repeated, reversed, and concurrent runs and records a SHA-256 verdict-vector
digest plus timing and allocation evidence. Its isolated-loader gate runs the
provider twice with different optional classpaths. Tests prove that both a
call-order-dependent validator and a classloader-resource-dependent validator
fail the gate.

The first-party bundle contributes `gs1-gtin-v1`. It accepts GTIN-8, GTIN-12,
GTIN-13, and GTIN-14 ASCII keys whose value is the same identifier encoded as a
canonical CBOR text string and whose final digit satisfies GS1 Mod-10. Its
parameter contract is the canonical empty CBOR map.

Primary verification commands:

```bash
./gradlew :core-api:test :plugin-catalog:test \
  :appchain-plugin-conformance:test \
  :appchain-authenticated-map-validators:test \
  :appchain-stdlib:test :appchain-devtools:test :runtime:test
```

Java validators remain trusted in-process consensus code. Digest pinning proves
which bytes were selected and conformance tests expose known nondeterminism; they
do not sandbox hostile bytecode or prevent direct filesystem, network, clock,
process, reflection, or thread access.
