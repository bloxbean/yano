# ADR-050 Phase 5 — Network, recovery and performance evidence

Date: 2026-08-31

## Result

Phase 5 passed on the deterministic devnet and a clean native preprod replay.
The devnet exercised every certificate-order/lifecycle scenario plus a real
process kill, startup recovery, graceful restart and two manual
rollback/replay passes. The preprod node reached tip with fail-fast epoch
calculation enabled and matched Koios treasury and reserves at every checked
epoch.

The clean mainnet replay remains the post-merge rollout step defined by this
ADR; it was not started as part of the preprod acceptance gate.

The clean preprod account store also exercised the new schema-readiness path:
startup atomically initialized `pool-lifecycle-state-v1` with the existing
epoch-boundary readiness markers before applying blocks. Store tests separately
prove that a populated store missing that marker and a store carrying an
unknown marker version both fail closed without modifying the store.

## Deterministic devnet matrix

`PoolLifecycleE2ETest` ran against a short-epoch, RocksDB-backed, signed devnet
with seven test-owned non-producing pools and 35 distinct delegators. The
genesis producing pool was never retired. All six tests passed:

- later-block retirement cancellation;
- effective retirement followed by re-registration in the retirement epoch;
- effective retirement followed by re-registration three epochs later;
- same-transaction `RetirePool -> RegPool`;
- same-transaction `RegPool -> RetirePool`; and
- both transaction-index orderings in one block.

The fixture also assigns scenario E's first stake credential to the
always-abstain DRep and verifies that vote delegation independently of its pool
delegation. An optional `YANO_POOL_RECOVERY_DESCRIPTOR` output makes the exact
pool, owner, DRep credential, reward baseline and retirement epoch available to
the external recovery drill without adding a production crash hook.

## Real-process recovery drill

Evidence directory:

```text
/Volumes/data2/yano-try/adr050-g-lite-20260831-attempt2
```

The JVM devnet used ports 7190/13350, a persistent chainstate, 60-slot epochs,
lazy block production, a 10-operation/4 KiB boundary chunk limit and
`yano.exit-on-epoch-calc-error=true`.

Before the boundary, target pool E had one live pool row, one epoch-15
retirement row, five pool delegations, one always-abstain DRep delegation and a
zero reward balance. The chain tip was slot 800 in epoch 13.

An external log follower sent `SIGKILL` to the Yano JVM when it observed:

```text
POOLREAP epoch 15 started: retiringPools=2, stage=delegations, nextSequence=1
```

That line is emitted after the initial progress marker is durable and before
delegation scanning starts. The restarted process found the body tip at slot
899 in epoch 14, reported boundary step 2, and resumed from the same durable
cursor:

```text
POOLREAP epoch 15 resuming: retiringPools=2, stage=delegations, nextSequence=1
```

Recovery completed before block production and REST readiness. It scanned 27
delegation rows, removed 10 pool delegations and six pool lifecycle rows,
credited two registered 500 ADA refunds in four chunks, and cleared the marker
in 4 ms. For target E, pool/retirement/pool-delegation rows were absent, the
DRep delegation remained, the owner reward was exactly 500 ADA and
`epoch-calc-status` returned `OK`. Producing the pending slot-900 boundary block
did not repeat the refund.

The devnet rollback endpoint then rolled slot 900 back to slot 899. The pool,
retirement and five pool delegations returned, the DRep delegation remained,
and the reward returned to zero. Two independent slot-900 replays both produced
this canonical live-state digest:

```text
500c13f516641be864cd3d39525209588b0f73f1e7388aebe23fadf5f6b9bef2
```

Both replays credited exactly 500 ADA. A final graceful process restart at
slot 900 retained the same digest, reward and `OK` status.

The first archive-enabled graceful restart exposed the already-separated
devnet archive/genesis-identity problem tracked by issue #105: the producer
rewrites `systemStart` after the archive identity is created. The recovery-only
fixture was restarted with projection history disabled. No #105 product change
is included in ADR-050, and the ledger chainstate remained sound.

## Admission and test-harness corrections found during validation

The running A–F matrix exposed two transaction-admission problems outside the
POOLREAP state transition but directly relevant to exercising pool updates:

- Yano's Java value-conservation rule charged a new pool deposit for every
  registration certificate. It now consults the transaction-start pool state,
  charges only genuinely new pool lifecycles and handles duplicate
  registrations in one transaction consistently.
- Scalus 0.18.2's produced-value API has the same structural problem because it
  receives no certificate state. Yano retains Scalus's standard rule set but
  swaps only that validator for a state-aware equivalent, guarded by tests that
  fail if the upstream rule set changes. The gap was also verified in Scalus
  1.1.1; the local override remains until an upstream fix is available.

The isolated integration test exposed a separate DuckDB JDBC classloader issue.
The archive manager now loads the driver explicitly before opening a connection.
This is a deterministic test/runtime hardening change and does not alter ledger
semantics.

At final branch head `c0ef6eb3`, a fresh isolated `:app:integrationTest` run
passed all 12 tests in five suites with zero failures, errors or skips in
2 minutes 12 seconds. The six-scenario external devnet matrix also passed with
zero failures.

## Acceptance conclusion

- Certificate ordering and lifecycle semantics pass the running-node A–F
  matrix.
- Deterministic checkpoint injection and a real `SIGKILL` both resume exactly
  once.
- Manual rollback restores live state and replay reproduces the same digest.
- DRep delegation and historical ownership remain independent of live pool
  cleanup.
- Preprod AdaPot is exact against Koios through tip.
- Schema readiness and the final isolated integration suite pass.
- Typical and maximum boundary times are far below the 60/120 second targets.
- Native memory stayed within the accepted approximately 1.5 GiB operating
  envelope on this run.
